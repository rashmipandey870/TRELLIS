# TRELLIS AI Models & Infrastructure Architecture

## 1. Overview
TRELLIS integrates an AI Gateway with a truthful provenance ladder:
1. **Live Model First**: Self-hosted local Ollama or configured Cloud API (Anthropic Claude).
2. **Database-Persisted Verified Pool**: High-quality pre-verified items generated previously by real models.
3. **Procedural / Curated Bank**: Clearly labelled procedural drills when live models are unavailable.
   - The UI explicitly renders `Generated by TRELLIS AI` only for model output, and `Practice bank` for procedural items.

## 3. Hardware Sizing & Deployment Specs

### Production Standalone Deployment (Self-Hosted Ollama)
- **Host**: 8 vCPUs (AMD EPYC or Intel Xeon), 32 GB RAM.
- **Accelerator**: 1x NVIDIA Tesla T4 (16 GB) or 1x NVIDIA A10G (24 GB).
- **Disk**: 100 GB NVMe SSD for model weights and cache.
- **Concurrency**: Up to 15 concurrent token streams via Ollama parallel slots (`OLLAMA_NUM_PARALLEL=4`).

### Production Cloud Burst Deployment
- **Host**: 4 vCPUs, 16 GB RAM (Stateless FastAPI API worker).
- **Latency Target**: p95 $< 1,200\text{ ms}$ for live generation; $< 250\text{ ms}$ for database pool queries.

## 4. Red-Team & Quality Gates
- **Double-Pass Key Verification**: Generated MCQs are solved independently by a second solver pass; items are rejected if the solver key disagrees with the generation key.
- **Code Execution Verification**: Coding problem reference solutions must pass 100% of generated test cases in the isolated CodeRunner before entry into the verified pool.
- **Wrong-Stub Failure Enforcement**: A deliberately faulty wrong stub must fail at least one test case.
- **PII Redaction**: All outbound prompts pass through automatic regex-based PII scrubbers (names, emails, phones, Aadhaar/SSN tokens) prior to API dispatch.
